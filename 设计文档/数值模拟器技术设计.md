# Balance Simulator 技术设计文档

> **版本**: v0.1
> **定位**: 独立于游戏本体的数值验证工具，供策划验证规则、调参、跑统计

```

                   │  config/     │  ← 共享配置
                   └──────┬───────┘
                          │
          ┌───────────────┼───────────────┐
          │               │               │
    ┌─────▼─────┐   ┌────▼────┐   ┌──────▼──────┐
    │  src/core │   │ src/core│   │ simulator/   │
    │ (游戏本体) │   │(模拟器) │   │ 特有模块      │
    └───────────┘   └─────────┘   └─────────────┘

         ▼               ▼
    Canvas 渲染      无渲染/纯数据
    玩家输入         AI 决策
```

核心模块（`src/core/`）是游戏本体与模拟器的**共用代码**，确保模拟结果与真实游戏行为一致。

## 三、配置文件结构

### 3.1 simulation.json — 模拟器运行参数

```json
{
  "runs": 500,
  "maxTurns": 100,
  "randomSeed": null,
  "parallelWorkers": 4,
  "outputFormat": ["csv", "json"],
  "outputDir": "./output/batch/",
  "collectPerTurn": true,
  "logLevel": "error"
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `runs` | int | 批量运行次数 |
| `maxTurns` | int | 单局最大回合数（超时判定平局） |
| `randomSeed` | int\|null | 随机种子，null=随机，指定值=可复现 |
| `parallelWorkers` | int | 并行 Worker 数（Node.js worker_threads） |
| `outputFormat` | string[] | 输出格式 |
| `collectPerTurn` | bool | 是否逐回合记录快照（影响性能） |
| `logLevel` | string | 日志级别 |

## 四、Simulation 生命周期

### 4.1 单次模拟流程

```
SimulationRunner.run()
  │
  ├─ 1. ConfigLoader.loadAll()
  │     ├── 加载 game-params.json
  │     ├── 加载 pieces.json, tiles.json, upgrades.json
  │     ├── 加载 enemies.json
  │     └── 加载地图模板
  │
  ├─ 2. GameState.init(config)
  │     ├── 创建 Board (棋盘 + 地块)
  │     ├── 放置玩家 (初始位置、初始资源)
  │     └── 放置敌人 (按模板或随机)
  │
  ├─ 3. AIController.init(strategy, gameState)
  │     └── 根据策略配置初始化 AI
  │
  ├─ 4. StatCollector.init()
  │     └── 注册事件监听
  │
  ├─ 5. WHILE (GameState 未结束 且 turn < maxTurns):
  │   │
  │   ├── TurnEngine.executeTurnStart(gameState)
  │   │   ├── PieceBehaviors.process()  // 棋子自主行为
  │   │   └── AIController.decide()     // 敌人AI决策
  │   │
  │   ├── TurnEngine.executeTurnPrep(gameState)
  │   │   ├── ResourcePool.collect()    // 收集资源
  │   │   └── ResourcePool.collectFruits()
  │   │
  │   ├── TurnEngine.executeTurnAction(gameState)
  │   │   └── AIController.act()        // AI执行操作+升级
  │   │
  │   ├── TurnEngine.executeTurnEnd(gameState)
  │   │   └── Board.produceResources()  // 地块产出
  │   │
  │   ├── TurnEngine.executeTurnTermination(gameState)
  │   │   └── Piece.consumeResources()  // 棋子消耗
  │   │
  │   ├── StatCollector.recordTurn(turn, gameState)
  │   │
  │   └── turn++
  │
  ├─ 6. StatCollector.finalize(result, gameState)
  │
  └─ 7. return SimulationReport
```

### 4.2 批量运行流程

```
BatchRunner.run(runs, config)
  │
  ├── 解析 parallelWorkers
  │
  ├── FOR i = 0 TO runs:
  │   ├── seed = config.randomSeed ? config.randomSeed + i : random()
  │   ├── RNG.reseed(seed)
  │   ├── map = MapGenerator.generate()  // Monte Carlo 随机地图
  │   ├── report = SimulationRunner.run(config, map)
  │   └── reports.push(report)
  │
  ├── AggregateReport = StatCollector.aggregate(reports)
  │
  └── Exporter.export(AggregateReport)
```

### 4.3 终局事件

| 事件 | 触发条件 |
|------|---------|
| `WIN_ALL_CLEAR` | 所有敌人被消灭 |
| `WIN_CAPTURE` | 指定地块被占领 |
| `WIN_BOSS_KILL` | Boss 被击杀 |
| `WIN_SURVIVE` | 存活到指定回合 |
| `LOSE_PLAYER_DEAD` | 玩家 HP <= 0 |
| `LOSE_DEADLOCK` | 无种子、无果、资源不足以转化 |
| `DRAW_TIMEOUT` | 超过 maxTurns |

## 五、核心数据结构

### 5.1 棋盘与地块

```typescript
interface Board {
  width: number;
  height: number;
  tiles: Tile[][];          // [y][x]
}

interface Tile {
  x: number;
  y: number;
  type: TileType;            // 'grassland' | 'fertile' | 'barren' | ...
  output: ResourceTriple;    // 每回合产出
  stock: ResourceTriple;     // 当前积存
  pieces: Piece[];           // 该格上的棋子
}

interface ResourceTriple {
  water: number;
  light: number;
  earth: number;
}
```

### 5.2 棋子

```typescript
type PieceType = 'seed' | 'root' | 'stem' | 'leaf' | 'flower' | 'fruit';

interface Piece {
  id: number;
  type: PieceType;
  owner: 'player' | 'enemy';
  hp: number;
  maxHp: number;
  active: boolean;           // 是否已扎根（经历过一次资源消耗）
  consumeCost: ResourceTriple; // 每回合消耗（从配置读取）
  atk: number;               // 攻击力（仅敌人棋子）
  def: number;               // 防御力（仅敌人棋子）
}
```

### 5.3 玩家状态

```typescript
interface PlayerState {
  x: number;
  y: number;
  hp: number;
  maxHp: number;
  atk: number;
  def: number;
  ap: number;
  maxAp: number;
  handFruit: number;
  upgrades: {
    atk: number;  // 0-5
    def: number;
    hp: number;
    ap: number;
  };
}
```

### 5.4 资源池

```typescript
interface ResourcePool {
  water: number;
  light: number;
  earth: number;
  nutrient: number;
}
```

### 5.5 敌人

```typescript
type EnemyAI = 'aggressive' | 'calm' | 'passive';

interface Enemy {
  id: number;
  templateId: string;
  x: number;
  y: number;
  hp: number;
  maxHp: number;
  atk: number;
  def: number;
  moveRange: number;
  attackRange: number;
  ai: EnemyAI;
}

interface EnemyTemplate {
  id: string;
  hp: number;
  atk: number;
  def: number;
  move: number;
  range: number;
  ai: EnemyAI;
}
```

### 5.6 游戏状态（顶层）

```typescript
interface GameState {
  board: Board;
  player: PlayerState;
  resources: ResourcePool;
  enemies: Enemy[];
  turn: number;
  phase: TurnPhase;
  result: GameResult | null; // null = 进行中
}

type TurnPhase = 'start' | 'prep' | 'action' | 'end' | 'termination';

type GameResult =
  | { type: 'win'; condition: string }
  | { type: 'lose'; condition: string }
  | { type: 'draw'; reason: string };
```

### 5.7 事件系统

```typescript
type GameEvent =
  | { type: 'PIECE_CREATED';      turn: number; piece: Piece; x: number; y: number }
  | { type: 'PIECE_DESTROYED';    turn: number; piece: Piece; cause: string }
  | { type: 'PIECE_ACTIVATED';    turn: number; piece: Piece }
  | { type: 'COMBAT';             turn: number; attacker: string; defender: string; damage: number }
  | { type: 'RESOURCE_COLLECT';   turn: number; water: number; light: number; earth: number }
  | { type: 'RESOURCE_PRODUCE';   turn: number }
  | { type: 'RESOURCE_CONSUME';   turn: number; pieceId: number; cost: ResourceTriple }
  | { type: 'UPGRADE';            turn: number; upgradeType: string; level: number }
  | { type: 'ENEMY_MOVE';         turn: number; enemyId: number; from: Pos; to: Pos }
  | { type: 'ENEMY_ATTACK';       turn: number; enemyId: number; target: string; damage: number }
  | { type: 'GAME_END';           turn: number; result: GameResult };
```

StatCollector 通过订阅事件来收集数据，与核心逻辑完全解耦。


## 六、StatCollector 接口

### 6.1 核心接口

```typescript
interface IStatCollector {
  // === 生命周期 ===
  init(): void;
  recordTurn(turn: number, state: GameState): void;
  finalize(result: GameResult, state: GameState): void;

  // === 事件订阅 ===
  onEvent(event: GameEvent): void;

  // === 报告 ===
  getReport(): SimulationReport;
  getTurnRecords(): TurnRecord[];

  // === 重置 ===
  reset(): void;
}
```

### 6.2 逐回合快照

```typescript
interface TurnRecord {
  turn: number;
  // 玩家
  playerHP: number;
  playerMaxHP: number;
  playerATK: number;
  playerDEF: number;
  playerAP: number;
  // 资源
  water: number;
  light: number;
  earth: number;
  nutrient: number;
  handFruit: number;
  // 棋子
  pieceCount: Record<PieceType, number>;
  totalPieces: number;
  activePieces: number;
  // 敌人
  enemyCount: number;
  totalEnemyHP: number;
  // 升级
  upgrades: { atk: number; def: number; hp: number; ap: number };
  // 回合内产量
  producedThisTurn: ResourceTriple;
  consumedThisTurn: ResourceTriple;
  collectedThisTurn: ResourceTriple;
  // 战斗
  damageDealtThisTurn: number;
  damageTakenThisTurn: number;
}
```

### 6.3 单次模拟报告

```typescript
interface SimulationReport {
  // 标识
  runId: number;
  seed: number;
  configHash: string;       // 配置的哈希（确保可复现）

  // 结果
  result: GameResult;
  totalTurns: number;

  // 汇总统计
  summary: SimulationSummary;
  // 逐回合快照（如果 collectPerTurn = true）
  turnRecords?: TurnRecord[];
  // 事件日志（如果 logLevel = debug）
  eventLog?: GameEvent[];
}

interface SimulationSummary {
  // 资源
  peakWater: number;
  peakLight: number;
  peakEarth: number;
  peakNutrient: number;
  totalWaterProduced: number;
  totalLightProduced: number;
  totalEarthProduced: number;
  totalNutrientProduced: number;
  totalFruitHarvested: number;

  // 棋子
  totalSeedsSown: number;
  maxPiecesOnBoard: number;
  piecesLostToStarvation: number;
  piecesLostToEnemy: number;

  // 战斗
  totalDamageDealt: number;
  totalDamageTaken: number;
  enemiesKilled: number;

  // 升级
  finalUpgrades: { atk: number; def: number; hp: number; ap: number };
  totalUpgrades: number;
  turnsToFirstUpgrade: number;

  // 经济
  turnsToBreakEven: number;    // 首次净收入 > 0 的回合
  turnsToFirstFruit: number;   // 首次收到果的回合
  fruitConversionRate: number; // 果 => 种的转化率
}
```

### 6.4 批量汇总报告

```typescript
interface BatchReport {
  totalRuns: number;
  configHash: string;

  // 胜负分布
  winRate: number;
  loseRate: number;
  drawRate: number;
  winConditionBreakdown: Record<string, number>;
  loseConditionBreakdown: Record<string, number>;

  // 回合分布
  avgTurns: number;
  medianTurns: number;
  minTurns: number;
  maxTurns: number;
  turnDistribution: number[];  // 直方图

  // 资源曲线（所有模拟的平均值）
  avgResourceCurve: TurnRecord[];   // 每回合平均快照
  percentile25Curve: TurnRecord[];  // P25
  percentile75Curve: TurnRecord[];  // P75

  // 升级分布
  avgFinalATK: number;
  avgFinalDEF: number;
  avgFinalHP: number;
  avgFinalAP: number;

  // 棋子存活率
  avgFinalPieceCount: Record<PieceType, number>;

  // Monte Carlo 分析（如果启用了随机地图）
  mapDifficulty?: {
    correlationWithWinRate: number;
    tileDensityEffect: number;
  };
}
```

## 八、技术选型

| 项目 | 选择 | 理由 |
|------|------|------|
| 语言 | TypeScript | 类型安全，与游戏本体共享 core/ |
| 运行时 | Node.js | 无浏览器依赖，支持 worker_threads 并行 |
| 配置格式 | JSON | 简单，可直接 diff，Excel/Python 可读 |
| 输出格式 | CSV + JSON | CSV 给 Excel 分析，JSON 给程序消费 |
| 随机数 | 自实现 SeededRNG | 保证可复现（拒绝 Math.random） |
| 并行 | Node.js worker_threads | 多核并行跑批量模拟 |
| 测试 | Vitest | 核心逻辑单元测试 |

## 九、与游戏原型的共享边界

```
balance-simulator/src/core/     <-->     原型/index.html
       |                                    |
       ├── Board.ts              <-->     board 逻辑（提取到 core）
       ├── Piece.ts              <-->     piece 逻辑（提取到 core）
       ├── TurnEngine.ts         <-->     回合阶段机（提取到 core）
       ├── CombatResolver.ts    <-->     伤害计算（提取到 core）
       ├── ResourcePool.ts       <-->     资源系统（提取到 core）
       └── UpgradeSystem.ts      <-->     升级系统（提取到 core）
```

**共享策略**：核心逻辑写一次（TypeScript），游戏原型通过编译为 JS 引入，模拟器直接 import。两边行为完全一致，不会出现「模拟器说平衡游戏里崩了」的情况。
